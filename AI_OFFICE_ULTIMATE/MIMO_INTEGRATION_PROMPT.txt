Интегрируй приложенный AI OFFICE ULTIMATE в существующий Bank Mandarin Pro отдельной вкладкой для владельца/администратора.

Работай точечно: сначала найди только маршруты, навигацию, авторизацию и слой хранения, которые нужны для интеграции. Не переписывай всю систему и не читай гигантские файлы целиком. Сохрани существующие данные и функции. Не запускай субагентов.

1. Прочитай README_RU.md, docs/INTEGRATION.md, server/app.mjs и server/core.mjs. Это готовый самостоятельный модуль, а не задание создавать весь интерфейс заново.
2. Размести клиент public/ по /ai-office/ с завершающим слешем. Подключи страницу во вкладку или iframe того же origin. CSS приложения изолируй страницей/iframe, не подмешивай глобально в существующий интерфейс.
3. Если сервер поддерживает Node 22.13+, можно использовать createOffice({root,origin,base:'/ai-office',authenticate}). authenticate(req) должен проверять существующую сессию Mandarin Pro и реальное право владельца, возвращать стабильный ID пользователя или null. Никогда не доверяй ownerId/role из клиентского тела или неподтверждённого заголовка. Сохрани исходный URL маршрута при передаче handler.
4. Если стек другой, перенеси API-контракт на текущий бэкенд с той же семантикой, а не создавай второй публичный незащищённый сервер. Адаптируй БД/файловое хранилище/секреты к инфраструктуре Mandarin Pro, сохраняя обязательную изоляцию владельцев во всех запросах. Не импортируй и не запрашивай реальные ключи в чате.
5. Используй существующую серверную защиту, HTTPS, проверку Origin/CSRF, лимиты запросов. Укажи точный публичный origin и prefix. Настрой reverse proxy Host правильно. Ключи ИИ должны оставаться на сервере и шифроваться ключом из системы секретов. Не отдавай .data через static; не сохраняй секреты в git/localStorage.
6. Добавь пункт AI Office только разрешённым владельцам. У учеников доступа быть не должно. Подключи журнал ошибок без ключей и чувствительных текстов. Защити файлы и задачи проверкой владельца. Предусмотри миграцию SQLite, если требуется перенос данных.
7. Сохрани параллельную обработку и частичные ответы, синтез, голосовую очередь, оригиналы документов и новые версии, генераторы DOCX/PPTX/XLSX. Не выдавай генерацию моделью за проверенные факты. Не разблокируй сложные Word-элементы без безопасной реализации.
8. Запусти npm test и браузерный smoke-тест: вход, проект, файл, ключ, чат, сравнение с одним отказавшим провайдером, синтез, импорт DOCX и изменение абзаца, DOCX/PPTX/XLSX скачать и открыть, PDF печать, голос. Отдельно проверь отсутствие доступа ученика к API и чужим файлам.
9. Объясни конкретные изменения и оставшиеся ограничения. Не публикуй приложение и не меняй production без моего указания.
